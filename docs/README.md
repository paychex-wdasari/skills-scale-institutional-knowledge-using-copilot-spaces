# OctoAcme Project Management Docs

## Overview

OctoAcme manages cross-functional projects through a lightweight lifecycle: initiate work by defining the customer or business need, success measures, stakeholders, and initial risks; plan approved work into prioritized, estimated increments with acceptance criteria, owners, dependencies, and a Definition of Done; then execute, release, and learn through retrospectives. Its approach emphasizes customer value, clear ownership, measurable outcomes, iterative delivery, and psychological safety.

The Project Manager coordinates schedules, delivery, risks, dependencies, and communication. The Product Manager defines outcomes, prioritizes the backlog, and measures impact; developers design, build, test, and document changes; QA validates acceptance criteria and quality; stakeholders contribute input and decisions. Teams use project boards, daily standups, weekly delivery and stakeholder updates, sprint or milestone demos, and a shared status source. Risks are tracked with owners and mitigations, reviewed regularly, and escalated through the PM, Product Lead, and sponsor as appropriate.

Quality is built into planning and delivery: work has explicit acceptance criteria and a Definition of Done; pull requests receive review and CI runs tests, linting, and security scans. Teams use unit and applicable integration tests, manual acceptance QA when needed, and smoke tests for critical flows and releases. Releases require passing checks, prepared release notes and rollback plans, staging and post-deployment verification, and stakeholder communication. Retrospectives after sprints, releases, milestones, and incidents turn lessons into a few owned, time-bound improvements.
